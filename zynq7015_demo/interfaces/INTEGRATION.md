# 摄像头与 HDMI 接入合同

现有硬件事实：器件 xc7z015clg485-2，顶层 s_wrapper，PS FCLK0 100 MHz 经 MMCM 得到 PL 150 MHz；两个 AXI-Lite 窗口为 0x43c00000/0x43c10000，视频控制为前者+0x8000。HDMI合入后的最终布线Slice占用11523/11550（99.77%），WNS+0.015ns、WHS+0.013ns；资源余量很小，任何新增PL逻辑需重新实现验证。

本轮已完成 HDMI_2 原生 TMDS 输出和2018.3布线检查，摄像头按用户要求暂不接入；仅摄像头接口保留，型号和时钟未指定。用户已确认物理点云画面可见，持续30FPS和SD重启仍需板测。

摄像头有三种接入方式：

1. 已有 Linux V4L2 驱动：`--camera /dev/videoN`，原生 960×720 GRAY8/YUYV，按返回的 bytesperline 处理行跨度，保留序号与单调时间戳。
2. 自定义驱动：实现 `video_port.h` 的 acquire/release。返回紧密 960×720 GRAY8，不可变缓冲；适配器完成复制后归还 lease。
3. 未来 PL DMA 直接写专用 DDR：使用 `LiveOrb::extractDdr()`，只允许原引擎的三个接收槽，物理地址 0x20800000、0x20900000、0x20a00000，槽步长 1 MiB。生产者完成整帧、缓存一致性与发布后再移交 lease；ORB 返回成功前不能写入同槽。若 PL 超时或报错，保留 DMA lease 并停止，必须复位／重载后恢复。该路径不进行输入 CPU 复制。

DDR 的 0x20000000 起 16 MiB 必须已被设备树完整 reserve 且 no-map。不能与 Linux 普通缓存别名同时映射。使用写合并驱动时，必须匹配真实内核配置和符号版本，保留内存屏障及 PL 写响应完成条件。应用只打开已有 UIO，不自动加载历史实验模块。

未来摄像头 PL 到系统时钟的跨域，应由确认后的传感器接口、成熟 AXI 视频桥接和异步 FIFO 承担。生产者只在完整帧提交后发布帧身份；溢出时丢弃整帧并留下序号缺口，不能把半帧作为完整图像。数据通路不允许反馈覆盖还在被描述子使用的 raw/blur 缓冲。

显示界面为 1280×720 RGB565，行跨度 2560 字节。`zslam_display_port.present_rgb565` 接收完整帧；返回前必须确认对该缓冲的 DMA 读取已完成，或者已复制到驱动自有缓冲。驱动负责 VDMA／扫描输出、双缓冲、vblank、像素时钟、复位和 CDC。两个输出帧共需3,686,400字节；本轮在原16MiB窗口经核对无冲突的尾部0x20b00000/0x20d00000各预留2MiB，复用同一UIO的WC映射，避免缓存别名。此布局不覆盖原ORB工作区或三个RX槽；不得额外打开另一个UIO映射。

当前配对HDMI链路使用原生TMDS扫描RTL和`--hdmi-uio`后端。后端与ORB共用单一映射，等待上一缓冲在vblank被确认后复制空闲缓冲、执行发布屏障、提交新基址和票据；最后一帧也等待确认，运行报告扫描/欠载/AXI计数。像素时钟74.25MHz，串行时钟371.25MHz，1280×720p60 DVI视频，无音频。另保留的framebuffer兼容后端不更改视频模式，为直接帧拷贝。原交接设备树会禁用与ORB地址重叠的旧视频设备，不能简单重新启用旧节点。

本轮已完成板卡/显示连接确认、帧所有权/屏障、跨域/复位仿真、完整顶层setup/hold/内部覆盖/DRC及物理HDMI显示。四个序列化TMDS外部边界没有接收器与PCB延迟模型，单独列出，不伪造外部时序值。整机吞吐、延迟、丢帧、内存、SD自启等按实际日志验收，详见`../HDMI_IMPLEMENTATION_ZH.md`。摄像头不在本轮范围；后续接入时仍需确认电气/时钟/真实标定及重新测量端到端性能。
