# 开机与桌面启动

本模块采用PS软件：systemd负责平台初始化，GNOME登录入口负责图形会话。复用已验证的DPU＋点云PL平台，7015原有ORB＋HDMI镜像保持原样。

开机顺序为工厂DFX启动 → `orb60-platform.service` → Ubuntu自动登录 → GNOME自启动入口 → 用户服务`orb60-manual-session.service`。平台服务核对固定资产哈希，依次加载固件、接口覆盖层和匹配驱动，执行点核小向量检查与DPU型号检查，再生成本次boot ID的新回执。每次成功启动只初始化一次，不重复加载正在工作的PL。未完成的加载会保留跨启动标记，禁止反复自动尝试。

桌面程序关闭自动锁屏、息屏与休眠，使用1024×768、60Hz。它继承实际登录会话的DISPLAY和XAUTHORITY，不固定`:0`或`:1`。相机和7015就绪后打开现有手动面板；有已保存地图时恢复持续定位，没有地图时等待用户开始建图。建图仍由用户点击开始及结束，结束保存后自动下发最近更新的当前地图。关闭面板只隐藏窗口。

GDM仅开启ubuntu自动登录，保留原账户密码及sudo认证。修改前的配置保存在板端项目根`startup_install_backups/`。未更换内核、启动镜像或7015位流。平台配置在`/etc/orb60/startup.json`，源文件或平台资产改变后需重新审核并运行安装器更新哈希。

在板端项目源码目录，以管理员权限执行一次安装：

```sh
sudo python3 orb60/kv260/startup/install.py --root "$(cd .. && pwd)" --install
```

日常查看：

```sh
systemctl status orb60-platform.service
systemctl --user status orb60-manual-session.service
```

平台回执在项目根`startup_runtime/<boot-id>/`，桌面启动记录在`desktop_startup/<boot-id>.json`，具体操作记录仍在`manual_sessions/`。启动检查失败会保留原错误，桌面不自动重载PL、不改用CPU ORB或录像。

在尚未建图时换线，面板保持运行并显示等待两板网络；直连后恢复最新地图定位。两板使用已有IPv6链路本地地址，不依赖路由器或DHCP。只有确认旧程序属于本项目、可执行文件哈希与相机标定匹配、错误确实是图像流断线、且渲染已经收尾时，才让旧程序正常退出并重新建立图像流。原始断线故障保留，不重置PL或地图，不强行删除资源锁。CRC、硬件或身份错误不会进入这条恢复路径。已开始建图后应保持两板网线连接，避免中断未保存的建图；中途断线不会假装本轮完整，也不会静默重置地图。

维护停止用户服务时，`stop_session.py`向属于本项目的实际控制进程发送结束请求，等待图像流明确结束、轨迹保存及资源释放。正常按钮不提供“结束定位”。
