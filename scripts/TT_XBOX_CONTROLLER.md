# TT + Xbox 控制站：3/5 确认、低限幅线性杆量与延时单条 stop 版

版本标识：tt-quorum3-linear30-stop1-delay2-20261004。实现选择：电脑/PS 软件，不修改 FPGA。
2026-10-04 最新要求：撤回 stop 五连发；四轴持续回中 2 秒后仅发一条，H 手动悬停立即发一条。
回中立即零 RC，任何一个轴离开死区就取消 stop 计时；不阻塞控制循环、不等待 stop 应答。
2026-09-04 用户明确要求：起飞五个副本收到三条成功回复即可放行，不足三条则等待后降落；
同时改善回中与过冲。此策略有意不同于官方 SDK 的 FIFO 等待，不再宣称完全等同官方分发。

本程序对齐前者。没有使用 EP 底盘控制或 EP 心跳协议。
保留本机 Windows 网卡绑定、视频显示、XInput 输入适配；未安装/切换整个 SDK 包。
对齐范围、源码版本和测试证据见 TT_SDK_CONTROL_REVIEW.md。

## 操作方式（已更新）

| 操作 | 行为 |
|---|---|
| LT + RT 同时压到至少 85%，保持 1 秒 | 起飞；不需要预先按 U |
| LB + RB / 键盘 L | 请求降落 |
| 键盘 H | 立即发一条 stop，不等应答；暂停杆量 |
| 键盘 U | 起飞已确认后，用于 H 之后恢复杆量；不能绕过起飞 3/5 条件 |
| 四个通道全部回中 | 立即零 RC，持续 2 秒后发一条 stop；持续回中不重复，新推杆立即恢复 |
| 键盘 R（窗口前台） | 开始 / 停止真实视频录制；不改变飞行状态 |
| Xbox Y（窗口可在后台） | 按一下开始录制，再按一下停止；按住不重复触发 |
| Esc / 正常关闭窗口 | 若本程序已请求起飞且尚未收到降落完成，发一次降落请求再退出 |

## 本版已移除的电脑端规则

- 地面每 5 秒发送 command，以及 3 秒/7.5 秒的通道锁定。
- 旧版的 10 秒起飞超时规则。现已按用户新要求采用 12 秒、3/5 判定的超时降落。
- 窗口失焦、视频/遥测过期、GUI 心跳慢、控制循环慢触发悬停/降落。
- 25% 起飞电量门槛、15% 自动降落门槛以及起飞/接管高度门槛。
- 起飞前 U 软件解锁、起飞后额外回中计时、每次运行只能起飞一次。
- 应答编号必须原样回显、对未知回复编号的拒绝。

视频/遥测新鲜度、电量、高度继续显示，但不参与飞行放行。
无人机固件自己的电量、链路保护没有修改。
因此视频冻结不会替操作者降落；操作者应能目视控制，必要时主动按 L/LB+RB。
程序崩溃、断网时不能保证任何命令送达。
正常关闭、Esc、Ctrl+C、GUI 主程序异常退出可进入关闭降落流程；
显式非零 -Seconds 到时也会关闭，默认 0 不计时。控制子进程自身崩溃无法保证降落。

## TT 指令与应答

- 起飞/降落仍发送 5 个 ReXX01..05 副本，保留官方 Flight 发包格式。
- 回包首两位组号按实际收到的学习，不要求与发送的 XX 相同，也不硬编码 01/02。
- 同一回复组的末两位副本编号 01～05 分别计数，至少三个不同副本 ok 即可确认。
  重复同一副本、其他组、错误回复和格式不合法的文本不增加成功数。
- 起飞最多等待 12 秒，不足三条就请求一次降落。判定截止后到达的回复不再算起飞成功。
- stop 使用官方 Flight.stop(retry=False) 对应的单条裸 stop；不使用五副本等待。
  普通 ok/error 没有唯一副本身份，因此不会计入起降 3/5，避免 stop 回复冒充起飞回复。
- H/U 和回中 stop 都不会凭空完成起飞确认，保留手动 L 降落优先级。
- 降落期间不持续发送 RC/stop；按键松开再按是新的人工请求。
- 正常关闭后的 20 秒是退出等待预算，不是飞行中的自动降落计时器。
  等待结束仍无应答会明确报告未知，不补发新的降落组。

关键边界：已识别的旧回复组会保留归属，不能拿剩余起飞回复充当降落回复。
如果起飞完全没有任何带编号回复，超时后仍会发 land，但此时无法区分后来未知组
属于旧起飞还是新降落，界面会保持 land=unconfirmed，不伪造“已落地”。
此时应目视确认停桨后关闭/重新启动。退出最多等待 20 秒，不额外发起起飞或重复降落。
当前不提供裸 ok 的弱计数回退；固件若只回裸 ok，须先确认协议，不用于这一编号 quorum 模式。
不支持同一程序运行中重启无人机、换电池后复用旧会话，或回复组号回绕/重用；
应落地停桨后重启控制站。文本回复没有鉴权，跨会话迟到包无法由编号严格证明身份。
只有一个控制程序使用 TT；不要同时用手机 App 和电脑控制站争抢连接。

## 摇杆映射

| 输入 | 动作目标 | SDK 通道 |
|---|---|---|
| 左摇杆上下 | 升降 | c |
| 左摇杆左右 | 转向 | d |
| 右摇杆上下 | 前后移动 | b |
| 右摇杆左右 | 左右平移 | a |

rc a b c d 的通道范围是 -100 到 100，不是电机功率百分比，也不是 cm/s。
官方 Flight.rc() 将四个输入直接格式化发出，函数内部没有额外的小限幅或缩放。
另一条 speed x 命令的 10～100 cm/s 不是 RC 杆量单位；不能把满杆解释为固定 1 m/s。
依据：[官方 Flight 源码](https://github.com/dji-sdk/RoboMaster-SDK/blob/ff6646e115ab125af3207a4ed3df42cc76c795b2/src/robomaster/flight.py)、
[TT SDK 3.0 手册](https://dl.djicdn.com/downloads/RoboMaster%20TT/Tello_SDK_3.0_User_Guide_en.pdf)。

适配器保持 20 Hz、15% 原始摇杆死区，四轴默认限幅 +/-30。
前后/左右改为去死区后的线性映射（XYExpo=1），升降和转向也保持线性，但共用的新限幅是 30。
右杆 20%、30%、50%、100% 分别输出约 2、5、12、30；旧 ±100 二次配置为 0、3、17、100。
因此最小有效杆量更容易产生指令，中大杆量及满杆更缓和；并非所有区间都提高输出。
这不是时间低通滤波，没有回中后持续衰减的非零尾巴；整数 RC 的四舍五入可能使极小输出为零。
这是用户最新要求的低速输入配置，替代之前的全范围 ±100 二次配置。
-RcLimit 仍可显式设 1 到 100，-XYExpo 可设 1 到 3。RC 30 不是 30 cm/s 或 30% 电机功率；
实际速度和制动距离需要人工实飞标定。

用户反馈右杆左打却向右飞，因此仅把横移符号从 -1 改为 +1；不再沿用此前示例注释推断。
当前符号为 (1,1,1,1)：正 RX/RY/LY/LX 分别映射 a/b/c/d，其他三个方向不变。
默认右杆打满左输出 rc -30 0 0 0，打满右输出 rc 30 0 0 0。
这是按用户实测纠正输入适配器；修改后的实际方向仍需人工验证。
参数 -RollSign/-PitchSign/-VerticalSign/-YawSign 可单独反转。

### 回中 stop 的确切行为

原版已经发送零 RC，不能把惯性简单说成“程序不处理回中”。本版增加的只是制动请求：

- 从有杆量输入变为左右两个摇杆的四轴均在原始 15% 死区内：立即发零 RC，启动 2 秒计时。
- 计时期间每 50 ms 继续发送零 RC；只在全部轴连续回中达到 2 秒时发一条普通 stop。
- 任何一个轴离开死区，立即取消计时并应用当前杆量；再次全部回中重新计时。
- 不阻塞等待，不等 stop 应答，不进入 stop 确认/锁杆状态；不使用 Re 编号。
- 持续居中时只发送零 RC，不重复 stop；新推杆下一周期恢复 RC，不需要按 U。
- 如果还在升降或转向，不因右杆单独回中而发全局 stop，避免打断其他轴的操作。
- 起飞等待/降落阶段不触发自动回中 stop；人工 H/L 的优先级保留。
- 初始进入 FLYING 且始终没有拨杆，不自动发 stop；H 立即发一条并清除延时 stop 计时。
- 不发送未经标定的反向杆量，不增加加减速时间平滑。不能保证消除物理惯性或瞬间刹停。

官方 stop 单包格式及 retry=False 见上述 Flight 源码；延时回中触发是本机输入策略，不是 SDK 原有计时。
普通 stop 应答不参与起飞/降落的编号应答计数。真实制动距离、网络延迟和原地漂移
仍须实机 A/B；本轮只做离线发包和状态测试。
