## P1

`precheck_memory.py` 使用 memtester 完整测试循环（重复直至至少7200秒），分配启动时
MemAvailable的70%，CPU4–7，CPU/DMC performance，至少7200秒，swap=0。
0.5秒保存温度、频率、可用内存；完成后drop_caches并对两段全PNG做三轮SHA256。
保存内核日志，退出恢复原CPU governor及DMC governor/min/max。

若最高频率检查有错误，保存原失败后在dmc_ondemand与次高固定1068MHz各重复
相同时长，仅用于诊断；不会自行宣布新频率适合B3或抹去失败。
`--diagnostic-short` 只用16MiB做脚本验收，状态为DIAGNOSTIC_ONLY或DIAGNOSTIC_FAIL，不能通过P1。
预装stressapptest来自rktoolkit，会自行绑核且不支持官方--no_affinity参数；
原短测试的hardware incidents保留为平台诊断，不宣称已验证A76-only条件。
不支持参数的启动失败单独保留，不能当作内存错误。

适配器用户照片铭牌：HT-PD27W-CN，最大27W；5.1V/5A、9V/3A、12V/2.25A、
15V/1.8A。这些是支持档位，实际PD协商电压不可读，不能据此断言板子输入5V或12V。
此前GCC9.4两次ICE Segmentation fault无OOM证据，正式C1重编成功，但原根因未确定；
缺失libg2o是clean-first引起的独立问题，不能解释ICE。

## P2 源码发现与修复范围

实际单目Frame构造调用 `ExtractORB(0, imGray, 0, 1000)`，B2独立生成器和
它的参考路径都用了 `{0,0}`。ORBextractor依赖该区间，重排关键点/描述子：
区间内的点从数组尾部递减写入，其余从首部递增写入。两段960宽和MH01的752宽
均小于1000，这些有效关键点全部进入反向写入分支。

因此之前V0与独立参考的逐字节一致只证明两个相同调用一致，未证明与实际
Frame使用数组顺序一致。初始化和匹配可受顺序影响，不能把B2的V0/native差异
直接归为多线程非确定性。修复生成器和参考的调用为 `{0,1000}`，保留算法点集、
描述子内容、层参数和SLAM后端；必须重新生成B3特征库，不能混用旧B2库。
原B2 CSV/raw和失败仍原样保留；旧单项结果只作为旧链路冒烟，不作新链路的正式消融。

提取器选择原条件还含 `(lastID - initID) < mMaxFrames`，并非仅由mState决定。
注入接口按实际传入extractor指针确定normal/initialization，并按整数纳秒文件名
读取，读取时还严格校验文件头时间戳。下一步须对两段前150帧两档全字段/描述子
逐字节比对，并逐帧核对选择记录；18:49前600帧native/V0各3次。
